The WindowsApps copy fallback exists because Microsoft Store installs can place Codex under C:\Program Files\WindowsApps, where direct child-process execution may be denied. When enabled, this plugin copies the Codex binary into your user profile and runs that copy instead.

The session-file fallback exists because the local Codex app-server can be unavailable or blocked. When enabled, this plugin reads the latest recorded rate-limit snapshot from ~/.codex/sessions, marks it as stale, and does not read Codex auth tokens.
